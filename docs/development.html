開発環境

WSL（Linux）から Windows 用の exe をクロスコンパイルする（cargo-xwin）。Rust と cargo-xwin のバージョンは mise.toml で管理している。clang / lld は mise では入れられないので apt で入れる。

# clang / lld / llvm-rc（cargo-xwin が Windows 向けのリンクと C/C++ のビルドに、build.rs がアイコンの埋め込みに使う）
sudo apt install clang lld llvm

# Rust・Windows ターゲット・cargo-xwin
mise install

よく使うコマンド

コマンド内容
mise run buildWindows 用 exe をビルドする。初回は MSVC CRT と Windows SDK のダウンロードで数分かかる
mise run deployビルドして、Windows のダウンロードフォルダの azarasi-voice-dev に exe を置く
mise run fmtコードを整形する
mise run lint整形のずれと clippy の警告をチェックする。警告もエラー扱い（CI と同じ）

動作確認

  • mise run deploy で置いた ダウンロード\azarasi-voice-dev\azarasi-voice.exe を起動する。開発用の exe は消し忘れないよう、目に付くダウンロードフォルダに置いている
  • 起動中の exe は上書きできないが名前は変えられるので、古い exe を azarasi-voice.old-<時刻>.exe に退避してから置く。使われなくなった退避分は次の deploy で消える
  • モデルと設定は、インストール版と同じ場所を使う
  • インストール版が起動していると、二重起動の防止で開発版は起動しない。先にトレイから終了する
  • ログを見たいときは --console を付けて起動する

初回セットアップ画面を試す

環境変数 AZARASI_VOICE_MODEL_DIR に空のフォルダを指定して起動すると、本物のモデルに触れずにダウンロードから試せる。

$env:AZARASI_VOICE_MODEL_DIR = "$env:TEMP\azarasi-setup-test"
& "$env:USERPROFILE\Downloads\azarasi-voice-dev\azarasi-voice.exe" --setup

Windows のスマート アプリ コントロールがオンだと、署名のない自作 exe は起動できない。開発中はオフにしておく必要がある。

build.rs

  • アイコンの埋め込み：src/icon_draw.rs で描いた画像から複数サイズの .ico を作り、llvm-rc でリソースにして exe に埋め込む
  • WSL からビルドするときの回避策：sherpa-onnx に同梱の ONNX Runtime は PathCch.lib をリンクしようとするが、xwin が展開する Windows SDK には pathcch.lib しかない。Linux ではファイル名の大文字小文字が区別されるので、正しい名前のシンボリックリンクを作ってリンク先に加える
