CI（.github/workflows/build.yml）

ジョブランナー内容
buildUbuntumise run lint と mise run build。exe と、build.rs が作った .ico を成果物にする
installerWindowsInno Setup でインストーラーを作る（Inno Setup が Windows 専用のため）
releaseUbuntuv* のタグのときだけ。インストーラーを GitHub Release に添付する

リリースの手順

  1. Cargo.toml の version を上げてコミットする
  2. 同じバージョンのタグを付けて push する
git tag -a v0.3.0 -m "azarasi-voice v0.3.0"
git push origin main v0.3.0

CI がインストーラー（azarasi-voice-setup-<バージョン>.exe）を作り、リリースノートを自動で生成して GitHub Release を作る。

リリースにはインストーラーだけを置く。exe 単体は置かない（インストール先が固定されるので、自動起動の登録が exe の移動でずれることがない）。

インストーラー（installer/azarasi-voice.iss）

  • 管理者権限なしで %LOCALAPPDATA%\Programs\azarasi-voice にインストールし、スタートメニューに登録する
  • インストール時に「Windows の起動時に自動で起動する」を選べる
  • AppId を固定しているので、新しいバージョンは上書きでアップデートされる。設定とモデルはそのまま残る
  • アンインストール時に、自動起動の登録・設定（%APPDATA%\azarasi-voice）・モデル（%LOCALAPPDATA%\azarasi-voice）も消す
  • インストール・アンインストールの前に、azarasi-voice が起動中なら終了を促す（AppMutex）
  • モデル（約 655 MB）はインストーラーに入れず、初回起動時にアプリがダウンロードする。アプリの更新のたびにモデルを落とし直さずに済む

手元で作るときは、Windows に Inno Setup 6 を入れて実行する。

ISCC /DAppVersion=0.0.0 /DExePath=<exe のパス> /DIconPath=<ico のパス> installer\azarasi-voice.iss

モデルを差し替えるとき

  1. 新しいモデルのファイルを、新しいタグ名の Release に添付する。アプリの「最新リリース」にならないよう --latest=false を付ける
  2. src/model.rs の BASE_URL と FILES（ファイル名・大きさ・SHA-256）を書き換える
  3. 古い Release は、古いバージョンのアプリが使い続けるので消さない
gh release create model-<名前>-v<番号> model.int8.onnx tokens.txt --latest=false --title "..." --notes "..."

コード署名

スマート アプリ コントロールがオンの PC でも起動できるよう、SignPath Foundation のオープンソース向けの無料署名を申請する予定。署名するのは、このリポジトリのソースから GitHub Actions でビルドしたものだけ。
