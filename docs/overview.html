方針

ゲームと並行して使えるように、待機中は軽く、話したときだけ重くなることを最優先にしている。

  • GPU / VRAM は使わない。音声認識は CPU で動かす
  • 待機中はキー入力の監視だけ。音声認識モデルは使うときだけメモリに載せる
  • 画面（設定・初回セットアップ）は別プロセスにし、閉じたらメモリごと消えるようにする

プロセス

すべて同じ azarasi-voice.exe で、引数によって役割が変わる。

起動のしかた役割
azarasi-voice.exe本体。タスクトレイに常駐し、ホットキー・録音・音声認識・貼り付けを行う
--settings設定画面。トレイのアイコンから本体が起動する
--setup初回セットアップ画面（モデルのダウンロード）。モデルが無いときに本体が起動する
--console本体と同じ。ログ表示用のコンソールを開く

二重起動の防止

名前付きミューテックス（本体は Local\azarasi-voice、設定画面は Local\azarasi-voice-settings）を作り、既にあれば何もせずに終了する（src/main.rs）。

  • ミューテックスはディスクには残らず、プロセスが終了すると Windows が自動で片付ける。ファイルで目印を作る方法と違い、異常終了しても「起動中ではないのに起動できない」状態にならない
  • インストーラーも同じ名前で、azarasi-voice が起動中かどうかを判定する（AppMutex）

子プロセスの後始末

本体は、設定画面とセットアップ画面を、ジョブオブジェクトに入れて起動する（src/child.rs）。ジョブには「最後のハンドルが閉じたら中のプロセスを終了させる」設定をしてあり、本体が終了すると、異常終了や強制終了でも、Windows が子プロセスを終了させる。子プロセスが起動した curl.exe も同じジョブに入る。

本体のスレッド

スレッド役割
メイン低レベルキーボードフックとトレイアイコン。Windows のメッセージループを回す
録音制御ホットキーの押下・解放を受けて、録音の開始・終了、効果音、設定の読み直しを行う
音声認識モデルの読み込み・解放と、音声を文字にする処理。結果をクリップボード経由で貼り付ける
モデル確認起動直後だけ動く。優先度を下げてモデルのハッシュを確認する
  • キーボードフックのコールバックでは、状態を更新してチャンネルに送るだけにしている。フックの中で時間のかかる処理をすると、Windows にフックを外されてしまう
  • トレイアイコンはメインスレッドでしか触れないので、他のスレッドからはスレッドメッセージ（WM_APP + n）で状態を伝える
